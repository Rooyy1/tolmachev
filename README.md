# Бот-консультант Никиты Толмачёва

Telegram-бот на aiogram 3: приветствие → каталог из 6 категорий товаров →
карточка товара → оплата через GetCourse → **автоматическая заявка тренеру**
в Telegram с юзернеймом, именем и купленным товаром.

## Структура проекта

```
tolmachev_bot/
├── bot.py                  # точка входа: polling бота + HTTP-сервер вебхука
├── config.py                # чтение .env
├── storage.py                 # sqlite: заявки на оплату (order_uid → кто/что купил)
├── requirements.txt
├── .env.example
├── Dockerfile
├── data/
│   ├── products.py             # все товары: цена, описание, ссылка GetCourse
│   └── texts.py                  # все тексты бота
├── handlers/
│   ├── start.py                    # /start, /menu, /whoami, "В начало"
│   ├── catalog.py                    # категории → карточка товара
│   ├── payment.py                      # кнопка "Оплатить" → генерация ссылки, "Я оплатил"
│   └── common.py                         # fallback на непредусмотренный ввод
├── keyboards/
│   ├── main.py
│   ├── catalog.py
│   └── product.py
└── webhook/
    └── server.py                # приём вебхука от GetCourse об оплате
```

## Как это работает целиком

1. Пользователь выбирает товар → жмёт **«Оплатить»**.
2. Бот создаёт запись в базе (`order_uid`, его Telegram id, username, имя,
   ключ товара) и присылает кнопку-ссылку на страницу оплаты в GetCourse,
   **добавив к ссылке `?order_uid=<уникальный код>`**.
3. Пользователь оплачивает на стороне GetCourse.
4. GetCourse при успешной оплате отправляет вебхук на наш сервер
   (`webhook/server.py`), в теле которого приходит и наш `order_uid`
   (потому что он был передан через доп. поле — см. настройку ниже).
5. Сервер находит по `order_uid` в базе, кто и что купил, и шлёт тренеру в
   Telegram сообщение вида:

   ```
   ✅ Новая оплата (GetCourse)
   👤 @username
   🛒 Товар: 4-дневный сплит под DDX
   💰 2 990 ₽
   ```

   Пользователю параллельно уходит подтверждение, что заявка получена.

Кнопка **«✅ Я оплатил»** — это ручной запасной вариант на случай, если
вебхук ещё не настроен или временно не дошёл: она сразу шлёт тренеру
пометку "не подтверждено платёжной системой, проверь вручную".

## Настройка GetCourse — что сделать именно вам

Это единственная часть, которую нельзя сделать за вас "в коде" — она
целиком настраивается в личном кабинете GetCourse под ваш конкретный
аккаунт. Три шага:

### 1. Создать предложения (offer) на каждый товар

В GetCourse: **Продукты → Предложения** — создайте предложение под каждую
позицию из `data/products.py` (14 штук) с нужной ценой. У каждого
предложения есть страница оплаты со своей ссылкой вида
`https://ваш-аккаунт.getcourse.ru/pay/xxxxx`.

Скопируйте эти ссылки в `data/products.py`, поле `gc_url`, вместо
плейсхолдеров `https://ВАШ_АККАУНТ.getcourse.ru/...`.

### 2. Добавить доп. поле `order_uid`, заполняемое из GET-параметра

Чтобы GetCourse "запомнил", какая именно заявка из бота оплачивается,
нужно одно доп. поле пользователя/заказа:

- **Пользователи → Настройки полей** (или **Настройки аккаунта → Доп. поля**)
  → создать текстовое поле с системным именем `order_uid`.
- В настройках этого поля включить **"заполнять значением из GET-параметра
  URL"** с тем же именем `order_uid`.

После этого, когда бот открывает ссылку вида
`https://ваш-аккаунт.getcourse.ru/pay/xxxxx?order_uid=a1b2c3d4e5f6`,
GetCourse сам подставит `a1b2c3d4e5f6` в это поле пользователя/заказа —
и дальше оно попадёт в вебхук.

*(Если в вашем интерфейсе GetCourse формулировки отличаются — ищите по
словам "доп. поле", "хранить значение из URL/GET-параметра". Функциональность
многолетняя и есть во всех тарифах GetCourse.)*

### 3. Включить вебхук на событие оплаты

**Интеграции → Вебхуки** (в некоторых версиях — **Аккаунт → Уведомления /
Внешние интеграции**) → добавить вебхук:

- **URL:** `https://ВАШ_ДОМЕН/getcourse/webhook/<GETCOURSE_WEBHOOK_SECRET>`
  (тот же секрет, что в `.env`, — он проверяется сервером и отсекает
  посторонние запросы на этот адрес)
- **Событие:** "Оплата заказа" / "Изменение статуса заказа на оплаченный"
  (формулировка зависит от версии GetCourse)
- **Формат:** JSON

**Важно:** ваш сервер с ботом должен быть доступен из интернета по HTTPS
(GetCourse не будет слать вебхуки на `localhost`). Варианты:
- Разместить бота на VPS с доменом и Nginx/Caddy + Let's Encrypt (Caddy
  сам получает HTTPS-сертификат, это проще всего).
- Для тестов — прокинуть локальный порт 8080 наружу через `ngrok` или
  `cloudflared tunnel`, и временно указать выданный HTTPS-адрес в вебхуке.

### Если формат JSON от GetCourse не совпадёт

Разные тарифы/версии GetCourse шлют вебхук чуть по-разному вложенным JSON.
Парсер в `webhook/server.py` ищет `order_uid` рекурсивно по всему телу
запроса, поэтому конкретная вложенность значения не важна — но если
GetCourse у вас всё же не пробрасывает `order_uid` в вебхук, в логах бота
будет видна строка `GetCourse webhook payload: {...}` с полным телом
запроса — по ней сразу видно, куда GetCourse на самом деле кладёт доп.
поля, и `_find_order_uid()` легко поправить под конкретную структуру.

### Альтернатива без своего сервера

Если поднимать свой HTTPS-эндпоинт не хочется, вебхук GetCourse можно
направить не на бота напрямую, а в конструктор вроде **Make (Integromat)**
или **n8n**, который примет вебхук от GetCourse и дальше сам дёрнет
Telegram Bot API (`sendMessage`) на чат тренера. Это избавляет от
необходимости держать свой сервер, но придётся вручную собрать текст
сообщения в конструкторе и там же прописать `chat_id` тренера и токен бота.
Штатная логика с `order_uid` (шаг 2) в этом случае не обязательна — просто
шлите в Telegram то, что GetCourse прислал о пользователе и товаре.

## Как узнать TRAINER_CHAT_ID

Telegram Bot API не умеет слать сообщения "по юзернейму" в личку — только
по числовому `chat_id`. Поэтому:

1. Тренер (`@tema.evgenevich`) открывает бота и пишет `/whoami`.
2. Бот присылает его `chat_id`.
3. Впишите это число в `.env` → `TRAINER_CHAT_ID`.

## Запуск

```bash
cp .env.example .env
# впишите BOT_TOKEN, TRAINER_CHAT_ID, GETCOURSE_WEBHOOK_SECRET

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python bot.py
```

## Запуск в Docker

```bash
docker build -t tolmachev-bot .
docker run -d --restart unless-stopped \
  --env-file .env \
  -p 8080:8080 \
  --name tolmachev-bot tolmachev-bot
```

Порт 8080 нужно прокинуть наружу (через reverse-proxy с HTTPS), чтобы
GetCourse мог достучаться до вебхука.

## Продакшен-заметки

- `MemoryStorage` для FSM — состояния (сейчас не используются активно, но
  задел есть) сбрасываются при перезапуске бота.
- `handlers/common.py` подключён последним и ловит любые необработанные
  сообщения и нажатия на устаревшие кнопки.
- `bot.delete_webhook(drop_pending_updates=True)` перед polling — на
  случай, если ранее был включён Telegram-вебхук (не путать с вебхуком
  GetCourse — это два разных механизма с похожим названием) или накопились
  старые апдейты.
- Заявки на оплату хранятся в SQLite (`orders.db`) — переживают перезапуск.
- Повторный вебхук по уже обработанной оплате не шлёт уведомление дважды
  (проверка поля `notified`).
