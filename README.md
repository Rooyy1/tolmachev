# Бот-консультант Никиты Толмачёва

Telegram-бот на aiogram 3: приветствие → каталог из 6 категорий товаров →
карточка товара → реквизиты для оплаты → клиент сам подтверждает оплату
кнопкой → **тренеру мгновенно приходит заявка** в Telegram с username,
именем и товаром.

## Структура проекта

```
tolmachev_bot/
├── bot.py                  # точка входа, регистрация роутеров
├── config.py                # чтение .env
├── requirements.txt
├── .env.example
├── Dockerfile
├── data/
│   ├── products.py             # все товары: цена, описание
│   └── texts.py                  # все тексты бота, включая реквизиты оплаты
├── handlers/
│   ├── start.py                    # /start, /menu, /whoami, "В начало"
│   ├── catalog.py                    # категории → карточка товара

│   └── common.py                         # fallback на непредусмотренный ввод
└── keyboards/
    ├── main.py
    ├── catalog.py
    └── product.py
```

## Как работает оплата

Это **не** автоматическая проверка платежа — оплата подтверждается самим
клиентом, а бот мгновенно передаёт эту информацию тренеру:

1. Клиент выбирает товар → жмёт **«Оплатить»**.
2. Бот показывает карточку товара и реквизиты:
   - Банк: Альфа-Банк
   - Телефон: +7 (900) 065-90-75
   - Получатель: Екатерина
3. Клиент переводит деньги переводом по номеру телефона.
4. Клиент жмёт **«✅ Я оплатил»**.
5. Бот **в этот же момент** отправляет тренеру в Telegram сообщение:

   ```
   🟢 Новая заявка на оплату

   👤 @username
   🙍 Имя: Иван Иванов
   🛒 Товар: 4-дневный сплит под DDX
   💰 2 990 ₽
   Статус: Оплачено (подтверждено клиентом в боте)
   ```

6. Тренер видит заявку и сам пишет клиенту в личные сообщения — дальше
   всё общение и фактическая проверка перевода идёт напрямую.

Никакой платёжной системы (GetCourse и т.п.) в этой версии не используется —
всё завязано на переводе по номеру телефона и подтверждении в боте.

## Как узнать TRAINER_CHAT_ID

Telegram Bot API не умеет слать сообщения "по юзернейму" в личку — только
по числовому `chat_id`. Поэтому:

1. Тренер (`@tema.evgenevich`) открывает бота и пишет `/whoami`.
2. Бот присылает его `chat_id`.
3. Впишите это число в `.env` → `TRAINER_CHAT_ID`.

Без этого шага бот будет молча пропускать заявки — сообщения о новой
оплате отправлять будет некуда.

## Запуск

```bash
cp .env.example .env
# впишите BOT_TOKEN и TRAINER_CHAT_ID

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python bot.py
```

## Запуск в Docker

```bash
docker build -t tolmachev-bot .
docker run -d --restart unless-stopped --env-file .env --name tolmachev-bot tolmachev-bot
```

## Креативы (фото-карточки товаров)

У каждого из 15 товаров есть свой креатив — `PRODUCTS[key]["photo"]` в
`data/products.py` хранит Telegram `file_id` картинки. Когда пользователь
открывает товар, бот присылает не голый текст, а фото с подписью и
кнопками под ним (`handlers/catalog.py`, `show_product`).

Если понадобится заменить картинку — пришлите новое фото этому же боту,
возьмите `file_id` из ответа (или через любой бот-инструмент вроде
@userinfobot/@RawDataBot) и замените значение поля `photo` у нужного товара.

**Важно:** `file_id` жёстко привязан к конкретному боту, который первым
принял это фото. Если вы смените `BOT_TOKEN` на токен другого бота — все
15 `file_id` перестанут работать, и бот на этот случай тихо откатится на
текстовую карточку без фото (см. `try/except TelegramBadRequest` в
`show_product`). Чтобы креативы продолжили работать на новом боте — нужно
заново переслать все 15 фото этому новому боту и обновить `file_id`.

Реквизиты для оплаты — в `data/texts.py`, константа `PAYMENT_REQUISITES_TEXT`.
Если номер телефона, банк или получатель поменяются — правьте только её.

## Продакшен-заметки

- `MemoryStorage` для FSM — состояния (сейчас активно не используются, но
  задел есть) сбрасываются при перезапуске бота.
- `handlers/common.py` подключён последним и ловит любые необработанные
  сообщения и нажатия на устаревшие кнопки — бот никогда не "зависает"
  молча и не оставляет "часики" на кнопке.
- `bot.delete_webhook(drop_pending_updates=True)` перед polling — на
  случай, если ранее был включён webhook или накопились старые апдейты.
- Кнопка «Я оплатил» подтверждает намерение клиента, но не сам факт
  перевода — окончательную проверку (пришли ли деньги) тренер делает
  сам, глядя в приложение банка, когда пишет клиенту в личку.
